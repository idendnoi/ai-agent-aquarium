# 멀티 AI 관리 위젯 대시보드 기획서 v2

> v1 대비 변경사항: 커뮤니티 유저 리서치(Hacker News, Reddit, Blind, 개인 블로그·뉴스레터) 결과를 반영해 문제 정의를 5개 페인포인트로 확장, 경쟁 분석 섹션 신설, 리스크 갱신, 부록에 원문 리서치 노트 병합

---

## 1. 프로젝트 개요

**한 줄 정의**
여러 AI(Claude, GPT, Gemini 등)를 동시에 쓰는 사용자를 위한, 화면 한쪽에 상주하는 소형 위젯형 통합 관리 대시보드. 각 AI에 이름을 붙이고 캐릭터화하여 사용성과 재미를 동시에 제공한다.

**핵심 컨셉**
- 실용 축: 여러 AI를 한 곳에서 관리·비교·전환
- 감성 축: 각 AI를 캐릭터로 의인화하여 애착과 재미를 부여
- 두 축의 결합이 기존 멀티 LLM 래퍼와의 차별점

**핵심 가설 (리서치 후 재정의)**
> 멀티 AI 사용자의 진짜 고통은 "창을 여는 수고"가 아니라 **"지금 각 AI가 어떤 상태인지 모르는 데서 오는 인지 부하"**이며, 캐릭터 시각화는 이 정보를 곁눈질만으로 전달하는 가장 효율적인 수단이다.

## 2. 문제 정의

### 2.1 관찰된 현상
- 문과·비전공 사용자: 대개 AI 1개(주로 Claude)만 사용
- 컴퓨터 관련 전공/개발자: AI 2~3개를 상시 병행 사용

### 2.2 왜 여러 개를 쓰는가 (주변 인터뷰)
> "각 AI, 에이전트마다 잘하는 게 달라서"

멀티 AI 사용자는 작업 유형별로 최적 AI를 암묵적으로 라우팅하고 있다. 예: 코드 리뷰는 Claude, 최신 정보 검색은 GPT, 이미지 관련은 Gemini.

### 2.3 커뮤니티 검증 기반 페인포인트 (5종)

| ID | 페인포인트 | 검증 강도 | 대응 기능 |
|---|---|---|---|
| **A** | 탭·앱 전환 피로 | 강함 (직접 증언 다수) | 위젯형 상주 UI |
| **B** | 어느 AI가 나은지 판단 불가 | 강함 (여론 완전 분열) | 벤치마크 스탯 카드 |
| **C** | 응답 대기 시간의 불투명성 → 몰입 붕괴 | 매우 강함 (가장 구체적) | 캐릭터 상태 시각화 |
| **D** | 맥락 재설명 비용 | 강함 | (신규 검토 필요) |
| **E** | 구독료 중복 부담 | 강함 (단, 해결 방향 상충) | 사용량·비용 대시보드 |

#### A. 탭·앱 전환 피로
같은 문제를 겪고 직접 도구를 만든 사람들이 다수 확인됨. 한 개발자는 복잡한 질문에 어느 모델이 나은 답을 주는지 알아보려 여러 모델 사이를 계속 왕복하다가 결국 세 모델에 동시 질문하는 크롬 확장을 직접 제작. 각 모델의 강점이 달라서(Gemini는 100만 토큰 초장문, ChatGPT는 벤치마크 선두, Claude는 자연스럽고 실용적) 하나만 고르지 못하는 상황을 문제로 지목.

#### B. 어느 AI가 나은지 판단 불가 — 여론이 완전히 갈림
Blind의 동일 스레드에서 "ChatGPT가 압도적으로 낫다"는 의견 바로 아래 "정반대 경험이다, Claude와 Gemini가 훨씬 좋다"는 반박이 달림. 다른 스레드에서는 "Claude가 제일 환각이 심하다"는 주장과 정반대 경험담이 병존.
→ **개인 체감으로는 판단 불가하다는 것이 커뮤니티 차원에서 입증됨.** 벤치마크 스탯 기능의 가장 강한 존재 근거.

#### C. 응답 대기 시간의 불투명성 (v2 신규 — 가장 중요한 발견)
Hacker News에서 나온 가장 구체적인 불만: 대기 시간이 얼마나 걸릴지 예측 불가능해서 기다릴지 다른 작업으로 넘어갈지 판단이 안 되고, 결국 시간만 때우게 되며, 백그라운드 작업 완료를 계속 경계하느라 몰입 상태에 진입하지 못하고 지쳐감.
→ **캐릭터화의 가장 실용적인 정당화 근거.** "지금 얘가 일하는 중인지, 얼마나 남았는지"를 곁눈질로 파악하게 하는 것 자체가 인지 부하를 줄임.

#### D. 맥락 재설명 비용 (v2 신규)
전환 피로의 본질은 "창을 여는 것"이 아니라 맥락을 매번 다시 설명하는 것. 커뮤니티 증언: 대화가 길어지면 "이 채팅이 너무 길어졌다"는 경고를 받거나 응답이 느려지고 환각이 늘어, 새 채팅을 열어 맥락을 복사·붙여넣고 상황을 처음부터 재설명하는 루프가 반복됨. 10개 앱·탭을 오가면 주의력이 파편화되어 "생산성의 착각"만 남은 채 하루가 끝난다는 지적.

#### E. 구독료 중복 부담 (해결 방향이 상충하므로 주의)
한 사용자는 여러 AI 구독료가 우스꽝스럽게 느껴져, ChatGPT는 일상 업무, Claude는 코딩, Gemini는 안드로이드 연동으로 쓰며 앱 사이를 계속 뛰어다니다 결국 하나로 통합. 업계 전반적으로 월 수백 달러대 최상위 요금제가 등장했고 무료·저가 요금제에는 크레딧 축소와 응답 지연 같은 제약이 늘어나는 흐름.
→ **주의**: 이 페인의 자연스러운 해결책은 "통합 관리 도구"가 아니라 **"쓰는 AI 개수 줄이기"**다. 이 방향으로 유저가 움직이면 본 제품의 시장 자체가 축소된다.

## 3. 타겟 사용자 세그먼트

| 세그먼트 | 특징 | 니즈 강도 | 캐릭터화 반응 |
|---|---|---|---|
| 개발자/엔지니어 | 용도별 AI 분업, 이미 IDE/CLI에 도구 내재화 | 실용 니즈 높음 | 낮음~중간 |
| 리서처/대학원생 | 답변 교차검증을 위해 여러 AI 동시 사용 | 매우 높음 (비교가 곧 워크플로우) | 중간 |
| 콘텐츠 크리에이터/마케터 | 결과물 톤에 따라 AI 구분 사용, UI 감성 중시 | 중간 | 높음 |
| 얼리어답터/테크 취미러 | 신모델 트렌드 추종, AI 성격 밈에 익숙 | 낮음~중간 | 매우 높음 |

**1차 타겟 (v2 조정)**: 페인 C(대기 시간 불투명성)를 가장 강하게 겪는 집단은 **에이전트·백그라운드 작업을 많이 돌리는 개발자**다. 다만 이들은 IDE 내재화로 이탈 유도가 어렵다는 상충이 있어, **리서처·크리에이터를 1차 진입점으로 하되 페인 C 대응 기능은 개발자 확장을 염두에 두고 설계**한다.

## 4. 핵심 기능 정의

### 4.1 MVP 기능
1. **위젯형 상주 UI** — 화면 구석 소형 상시-켜짐 창 (Tauri 기반) `→ 페인 A`
2. **AI별 캐릭터화** — 이름 부여, 캐릭터 이미지/표정, 성격 프리셋
3. **AI 상태 실시간 시각화** — 응답 대기 중 여부, 예상 소요 시간, 진행 상태를 캐릭터 표정·애니메이션으로 표현 `→ 페인 C (최우선)`
4. **벤치마크 기반 스탯 카드** — 공개 벤치마크를 캐릭터 능력치(코딩/추론/속도/가격)로 매핑 `→ 페인 B`
5. **사용량·비용 대시보드** — API 사용량과 예상 비용을 캐릭터 체력바로 표현 `→ 페인 E`

### 4.2 확장 기능 (2차)
6. **작업 기반 자동 추천/라우팅** — 프롬프트 유형 분석 후 해당 분야 강점 AI 추천 `→ 페인 B`
7. **공유 컨텍스트 저장소** — 자주 쓰는 맥락(프로젝트 정보, 작업 스타일)을 위젯에 저장해 어느 AI로 보내든 자동 첨부 `→ 페인 D (v2 신규)`
8. **크로스체크 뷰** — 동일 질문 동시 전송 후 나란히 비교 (리서처 타깃)

> **v2 우선순위 변경**: v1에서 부가 기능이던 "상태 표시"가 커뮤니티 검증 결과 **가장 강한 페인에 대응하는 핵심 기능**으로 승격. 반대로 "응답 톤 리라이팅"은 근거가 약해 후순위로 강등.

## 5. 경쟁 분석 (v2 신설)

### 5.1 직접 경쟁 제품

| 제품 | 형태 | 포지셔닝 | 가격 |
|---|---|---|---|
| **ChatPlayground AI** | 크롬 확장 | 25개 이상 모델 결과를 한 창에서 나란히 비교, 탭 전환 없이 각 모델 강점 활용 + 다중 구독료 회피 | 라이프타임 $79 (정가 $619) |
| **OkuChat** | 웹/iPhone 앱 | GPT·Claude·Gemini를 하나의 구독으로 통합 | 월 $13 |
| **TabGPT** | 크롬 확장 (오픈소스) | 한 번의 프롬프트로 3개 모델에 동시 질문, 답변 취합 | 무료 |
| Poe / TypingMind / LibreChat / ChatHub | 웹앱 | 범용 멀티 LLM 인터페이스 | 다양 |

### 5.2 시사점
**"멀티 AI 통합"만으로는 이미 레드오션이다.** 위 제품들이 이미 페인 A(탭 전환)와 E(구독료)를 직접 겨냥하고 있다.

### 5.3 우리의 차별화 3축

| 축 | 내용 | 경쟁 제품 대비 |
|---|---|---|
| ① **폼팩터** | 브라우저 확장/웹앱이 아닌 **데스크톱 상주 위젯** | 경쟁 제품 대부분이 브라우저 기반 — 이 폼팩터는 비어 있음 |
| ② **상태 시각화** | 대기 시간·사용량을 캐릭터 표정으로 전달 | 어느 경쟁 제품도 미제공. 페인 C를 정면으로 겨냥 |
| ③ **근거 기반 추천** | 벤치마크 수치를 스탯화해 축별 비교·추천 | 경쟁 제품은 "나란히 보여주기"까지만, 판단은 유저 몫 |

> 결론: 경쟁 제품은 "여러 AI를 **한 번에 보여주는**" 데 집중한다. 본 제품은 "여러 AI를 **한눈에 관리하는**" 데 집중해 포지션을 분리한다.

## 6. 벤치마크 데이터 활용 방안

### 6.1 참고 가능한 소스
| 사이트 | 특징 |
|---|---|
| llm-stats.com | 300+ 모델, 코딩/추론/속도/가격 종합 점수, API 제공 |
| benchlm.ai | 407개 벤치마크, 8개 카테고리 가중 평균, 신뢰도(Confidence) 별도 표기 |
| kilo.ai/leaderboard | 실사용 데이터 기반(합성 벤치마크 아님) |
| agentguides.dev/leaderboard | 각 점수에 출처 URL·측정일 명기 |
| vellum.ai/llm-leaderboard | 최신 SOTA 모델 사이드바이사이드 비교 |

### 6.2 단계별 접근
1. **1단계 (MVP)**: 수동 수집 → 정적 JSON으로 캐릭터 스탯 구성. 구현 빠름
2. **2단계**: API 연동으로 신모델·벤치마크 갱신 시 자동 반영
3. **3단계**: 벤치마크 기반 프롬프트 자동 라우팅

### 6.3 주의사항
- 벤치마크마다 순위가 달라 절대 1위를 단정하지 않고 **축별로 분리 표기**
- 각 스탯에 출처·측정 시점 명기 (예: "SWE-bench, 2026-08 기준")
- **커뮤니티 여론이 극도로 분열되어 있으므로**, "우리가 정답을 안다"는 톤은 반발을 유발. "이 축에서는 이 수치"라는 중립적 제시가 안전

## 7. 기술 스택(제안)

- **앱 프레임워크**: Tauri + React (Electron 대비 경량, 상주 위젯에 적합)
- **API 연동**: OpenAI, Anthropic, Google 등 각사 API 직접 호출
- **로컬 보안**: API 키 로컬 암호화 저장 (평문 저장 금지)
- **벤치마크 데이터**: 정적 JSON(1단계) → 리더보드 API(2단계)
- **상태 시각화**: 캐릭터 애니메이션 — Lottie 또는 SVG 스프라이트
- **컨텍스트 저장소**: 로컬 DB(SQLite) 기반, 프롬프트 자동 프리픽스 주입

## 8. 리스크 및 검증 필요 사항

| 리스크 | 심각도 | 대응 방향 |
|---|---|---|
| **구독료 페인의 해결책이 "통합"이 아니라 "축소"** — 유저가 AI를 1개로 줄이면 시장 자체가 소멸 | 높음 | 구독료 절감을 소구점으로 삼지 말 것. "이미 여러 개 쓰는 사람"만 타깃 |
| 직접 경쟁 제품(ChatPlayground, OkuChat, TabGPT) 다수 존재 | 높음 | 차별화 3축(위젯 폼팩터·상태 시각화·근거 기반 추천)에 집중, 기능 중복 회피 |
| 개발자 세그먼트는 IDE/CLI에 도구 내재화되어 이탈 유도 어려움 | 중간 | 1차 타깃을 리서처·크리에이터로 진입 |
| 벤치마크 점수의 신뢰성 논쟁, 커뮤니티 여론 분열 | 중간 | 단일 점수 대신 축별 비교, 출처 명시, 중립적 톤 |
| 각 AI사 API 정책·약관상 위젯 사용 제약 가능성 | 중간 | 각 API 이용약관 사전 확인 |
| "캐릭터화"가 개발자에게 유치하게 느껴질 가능성 | 중간 | 캐릭터 표시 on/off 토글 제공, 실용 정보는 캐릭터 없이도 읽히게 설계 |

- **인용 가치**: 페인 D(맥락 재설명 비용)의 가장 구체적 묘사

## D. 신뢰·경계 피로

**출처 7 — Siddhant Khare 블로그, "AI fatigue is real and nobody talks about it"**

## 리서치 종합 판단

**강하게 검증된 것**
- 멀티 AI 사용자의 탭 전환 피로는 실재하며, 이미 여러 사람이 자작 도구를 만들 만큼 절실함
- 모델 우열에 대한 개인 체감은 신뢰할 수 없을 만큼 분열되어 있음 → 객관 지표 니즈 존재
- **응답 대기 시간의 불투명성이 몰입을 파괴한다는 페인이 가장 구체적으로 서술됨** (v1에서 과소평가했던 지점)

**반증 또는 주의가 필요한 것**
- 구독료 페인의 자연스러운 귀결은 "통합"이 아니라 "축소"
- 동일 문제를 겨냥한 상용 제품이 이미 다수 존재 (레드오션)

**미검증 — 직접 인터뷰 필요**
- 캐릭터화가 실제로 사용 만족도를 높이는지 (커뮤니티에서 관련 발화 미발견)
- 데스크톱 상주 위젯 폼팩터에 대한 실제 선호도
- 페인 C를 겪는 사용자가 이를 "해결해야 할 문제"로 인식하는지, 아니면 감수하는 조건으로 여기는지
